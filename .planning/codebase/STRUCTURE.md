## Directory Purposes

**`.github/workflows/`:**
- Purpose: CI/CD definitions for GitHub Actions
- Contains: Hugo build + Pages deploy workflow (Hugo 0.159.1 extended, `--gc --minify`, baseURL `https://www.cingparty.uk/`)
- Triggered by: push to `main`, manual `workflow_dispatch`

**`archetypes/`:**
- Purpose: Front-matter templates for `hugo new` scaffolding
- Key files: `archetypes/default.md` (104 bytes, default front matter)

**`content/`:**
- Purpose: Markdown for every page on the site
- Contains: section index files (`_index.md`) and individual posts under `news/` and `press/`
- Front-matter convention: `title`, `description`, optional `layout`, `overline`, `date`, `image`, `category`, `excerpt`

**`data/`:**
- Purpose: Structured data accessed via `hugo.Data`
- Key files: `data/councillors.yaml` (44 lines, single source for `/councillors/` and `/about/`)

**`docs/`:**
- Purpose: Version-controlled durable reference (brand standards, manifesto prose, project README of docs)
- Distinct from `.reference/` which is gitignored Stitch HTML exports

**`layouts/`:**
- Purpose: Custom Hugo Go-templated HTML — no theme is used
- Convention: page templates inherit `_default/baseof.html` via `{{ define "main" }}`

**`public/` (GITIGNORED):**
- Purpose: Hugo's emitted static site — generated by every `hugo` invocation
- Never edited by hand; never committed

**`resources/` (GITIGNORED):**
- Purpose: Hugo's internal asset cache (image processing artefacts, etc.)

**`scripts/`:**
- Purpose: Python utilities for branded press release asset generation
- Run locally before committing assets to `static/`

**`static/`:**
- Purpose: Files copied verbatim into `public/` at the site root
- Contains: favicons, `CNAME`, `robots.txt`, `images/`, `documents/`

**`.reference/` (GITIGNORED):**
- Purpose: HTML snapshots exported from Google Stitch (project ID `3771371856444129928`) used as design source of truth
- Contains: e.g. `cing-policies-manifesto.html`
- Never deployed; consult during template work

**Section indexes** (`_index.md`) declare front matter such as `title`, `description`, `overline`, and (where required) `layout`. Example: `content/policies/_index.md` sets `layout: "policies"` to pick `layouts/policies/policies.html`.

**Press subfolder convention:** releases relating to a single Cornwall Council meeting live under `content/press/full-council-<date>/`, with an `_index.md` for the meeting landing page.

**`_incoming/`** uses cascading `build` front matter to keep raw drafts unpublished while still tracked in git.

## Data Directory

**`data/councillors.yaml`** (44 lines) — single source for councillor records. Each record has:

| Field | Type | Notes |
|-------|------|-------|
| `name` | string | Display name |
| `role` | string | "Group Leader", "Deputy Leader", "Member" |
| `division` | string | Council ward(s) |
| `photo` | string | Path under `/images/councillors/` |
| `email` | string | Cornwall Council email |
| `attendance` | int | Percentage (e.g. `90`) |
| `bio` | string | Short biographical paragraph |
| `committees` | string[] | Committee memberships |
| `outside_bodies` | string[] | (optional) external appointments |

Read in templates via `{{ $councillors := index hugo.Data "councillors" }}`. Consumed by `layouts/councillors/list.html` (full grid) and `layouts/about/list.html` (team bento).

## Scripts Directory

**`scripts/generate_press_heroes.py`:**
- Generates 1600×800 navy-gradient hero JPGs into `static/images/press/<slug>.jpg`
- Uses Pillow (`PIL.Image`, `ImageDraw`, `ImageFilter`, `ImageFont`)
- Brand tokens hard-coded: navy `#00263b`/`#003d5b`, gold `#705d00`/`#c9a900`
- Releases declared inline as a list of `@dataclass` records (slug, headline, overline, motif)

**`scripts/generate_press_pdfs.py`:**
- Generates branded multi-page A4 PDFs into `static/documents/press/2026-04-21/<slug>.pdf`
- Uses `reportlab` (`BaseDocTemplate`, `Frame`, `Paragraph`, `TTFont`)
- Reads release source markdown from a configured `SOURCE_DIR` outside the repo
- Embeds Poppins (Manrope proxy) and Lato (Public Sans proxy) for brand-true type
- Output includes first-page banner, embargo strap, pull quotes, and contact footer

Both scripts are invoked manually; their outputs are committed to `static/`.

## Generated / Excluded Directories

Per `.gitignore`:

- `public/` — Hugo build output (regenerated every build; served as the live site by GitHub Actions)
- `resources/` — Hugo's internal cache (image transforms, etc.)
- `.hugo_build.lock` — transient build lock
- `.reference/` — Stitch HTML exports (design source; not deployed)
- `.playwright-mcp/` — local Playwright MCP scratch
- `.claude/` — local Claude Code state
- `*.png` (with explicit allowlist for `static/favicon-32x32.png` and `static/apple-touch-icon.png`)

## Naming Conventions

**Files:**
- Markdown content: `kebab-case.md` (e.g. `welcome-to-our-new-website.md`, `mevagissey-school-transport.md`)
- Section indexes: `_index.md` (Hugo convention)
- Layouts: `kebab-case.html`, with section names matching content folders
- Images: `kebab-case.jpg|png|svg`; press hero filenames match the release slug
- PDFs: per-release filename matches the content slug

**Directories:**
- All lowercase kebab-case (`get-involved/`, `full-council-2026-04-21/`)
- Date-stamped meeting folders use `YYYY-MM-DD` order via `<event>-YYYY-MM-DD/`

**Slugs:** content slug = filename stem; the same slug threads through `content/press/.../<slug>.md`, `static/images/press/<slug>.jpg`, and `static/documents/press/<date>/<slug>.pdf`.

## Where to Add New Code

**New news post:**
- `hugo new content/news/my-post-title.md`
- Set `title`, `date`, `category`, `image`, `excerpt` in front matter
- Image (if used) goes into `static/images/` and is referenced by absolute path

**New press release for an existing meeting:**
- Add markdown at `content/press/<meeting-folder>/<slug>.md`
- Add hero JPG at `static/images/press/<slug>.jpg` (or extend `scripts/generate_press_heroes.py` and re-run)
- Add PDF at `static/documents/press/<date>/<slug>.pdf` (or extend `scripts/generate_press_pdfs.py` and re-run)

**New press meeting:**
- Create `content/press/<event>-YYYY-MM-DD/_index.md` with `title`, `date`, `description`
- Create `static/documents/press/YYYY-MM-DD/` for PDFs
- Add a release entry inside the scripts' `RELEASES` list if scripted generation is desired

**New councillor:**
- Append a record to `data/councillors.yaml` with all fields
- Drop a portrait at `static/images/councillors/<slug>.jpg`

**New top-level section:**
- Create `content/<section>/_index.md`
- Add a section template at `layouts/<section>/list.html` (and `single.html` if posts are listed)
- Add a menu entry in `hugo.toml` under `[[menus.main]]`

**New page-only layout:**
- Add a template at `layouts/<type>/<name>.html`
- Reference it from a content file's front matter via `layout: "<name>"` (see `content/policies/_index.md`)

**Shared chrome change:**
- Edit `layouts/_default/baseof.html` (head, GA, banner) or `layouts/partials/{header,footer}.html`

**New static asset:**
- Drop into `static/` at the path matching its desired URL
