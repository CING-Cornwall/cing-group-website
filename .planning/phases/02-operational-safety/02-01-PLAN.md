    ```yaml
          - name: Embargo guard — fail on future-dated press outside _incoming/
            run: |
              set -euo pipefail
              python3 - <<'PY'
              import datetime, pathlib, re, sys
              now = datetime.datetime.now(datetime.timezone.utc)
              root = pathlib.Path("content/press")
              violations = []
              for md in root.rglob("*.md"):
                  if "_incoming" in md.parts:
                      continue
                  text = md.read_text(encoding="utf-8")
                  m = re.search(r"^publishDate:\s*(\S+)", text, re.MULTILINE)
                  if not m:
                      continue
                  try:
                      pd = datetime.datetime.fromisoformat(m.group(1).replace("Z", "+00:00"))
                  except ValueError:
                      continue
                  if pd.tzinfo is None:
                      pd = pd.replace(tzinfo=datetime.timezone.utc)
                  if pd > now:
                      violations.append(f"{md}: publishDate {pd.isoformat()} is in the future")
              if violations:
                  print("Embargo guard failed:", file=sys.stderr)
                  for v in violations: print("  " + v, file=sys.stderr)
                  sys.exit(1)
              print("Embargo guard: no future-dated press files outside _incoming/.")
              PY
    ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Repo `main` → public site | Anything rendered on `main` ships to `www.cingparty.uk` immediately on push and on cron |
| `content/press/_incoming/` → public site | Excluded by cascade `build.render: never`; this is the trusted-staging boundary |
| GitHub Actions runner → external | Runner pulls source from `main`, builds with Hugo, deploys to GitHub Pages — no third-party network access introduced this plan |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01-01 | T (tampering) — embargo bypass via misnamed file | Press content directory | mitigate | Guard step uses `md.parts` membership check (not substring), so files like `_incoming-notes.md` outside the `_incoming/` directory cannot be falsely excluded |
| T-02-01-02 | I (information disclosure) — future-dated press accidentally on `main` rendered before embargo | `content/press/**` outside `_incoming/` | mitigate | Embargo guard fails CI before `Build with Hugo` runs; build artifact is never produced when violation exists |
| T-02-01-03 | D (denial of service) — embargo lift silently missed | Embargoed press waiting in `_incoming/` past its `publishDate` | mitigate | `schedule:` trigger fires 4× daily; deploy gate broadened so cron events also deploy. Operationally, a missed lift becomes detectable as "press visible at a worst-case 5-hour delay rather than never" |
| T-02-01-04 | E (elevation) — write access to `main` bypasses embargo manually | Branch protection on `main` | accept | Branch protection (required PR + required `build` check + admin-enforced) was shipped before initialization (PROJECT.md "Validated requirements"). The guard step runs in the required `build` check and therefore blocks merge of any future-dated press file |
| T-02-01-05 | R (repudiation) — silent cron failure leaves embargo missed | GitHub Actions schedule reliability | accept | GitHub publishes Actions reliability stats; 4× daily redundancy means a single missed cron is recoverable. A persistent failure surfaces as visible "no recent runs" in the Actions tab. No additional alerting in scope this phase |

All five threats addressed; no `high`-severity items left unmitigated. Block-on-high gate satisfied.
