# Plan 01-01: Privacy & analytics consent gating

**Phase:** 1 — Privacy & press toolchain
**Status:** Ready to execute
**Requirements covered:** PRIVACY-01, PRIVACY-02, PRIVACY-03 (+ INTEGRATIONS.md doc-sync)

## Goal

Make the site's analytics behaviour match the privacy promise: the GA `gtag/js` script must not be injected, and no requests must reach `googletagmanager.com` or `google-analytics.com`, until a visitor explicitly accepts the cookie banner. Then bring the privacy page markdown and the AI-guidance docs into lockstep with that behaviour, so the public privacy claim, the codebase map, and the inline implementation all describe the same flow.

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Ad blocker (uBlock, Brave shields, Privacy Badger) suppresses requests in the verification step, hiding a real bug | Verify in a clean Chrome or Firefox profile with no extensions. Document this explicitly when running Task 4. If using a personal browser, open an incognito/private window with extensions disabled. |
| `gtag` becomes referenced before defined (e.g. an Accept handler runs before the head script parses) | Not possible in practice — `gtag` is defined synchronously in `<head>`, the banner script runs after `</body>`. But if a future template change moves the banner into `<head>`, this assumption breaks. Task 3 keeps the banner script at the bottom of the body. |
| Double-load on rapid Accept → clear localStorage → Accept | `gtagLoaded` idempotency flag in `loadGtag()` prevents duplicate script tags. Task 2 must not omit this flag. |
| Pre-existing visitors with `localStorage['cing-cookies'] === 'accepted'` are continued under "old" consent terms | Per RESEARCH.md A4, this is acceptable: the consent was to "Google Analytics for anonymous usage statistics", which is what they continue to get. No re-prompt. Note this in the PR description so the maintainer can override if they want a stricter posture (clear localStorage on deploy → forces banner re-show). |
| Markdown fix accidentally promotes one of the four headings to H1 (e.g. typing `# What data we collect` instead of `## What data we collect`) | Task 6 explicitly says "single space after `##`, no level change". Verification §2 grep is for `<h2[^>]*>...</h2>` specifically, so an accidental H1 would fail. |
| `INTEGRATIONS.md` rewrite drifts from the actual implementation | Task 9 names the function (`loadGtag()`) and call sites (page-load + Accept handler), which match Task 2. If those don't match, INTEGRATIONS.md is wrong; if they do, INTEGRATIONS.md is right. |
| Production-only `{{ if hugo.IsProduction }}` gate is accidentally removed | Task 2 explicitly says the wrapper stays. Verify after edit by running `hugo server` (dev mode, not `IsProduction`) and confirming no `<script>` related to `loadGtag` appears in the rendered HTML. |
