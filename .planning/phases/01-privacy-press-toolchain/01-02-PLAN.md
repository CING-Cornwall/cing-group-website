## Risks and mitigations

| Risk | Mitigation |
|---|---|
| `reportlab` or `Pillow` not installed locally | Task 4 includes the `pip install` step. Out-of-scope for full pinning — that's Phase 3 BUILD-02. Document the install step in the PR body so future verifiers don't assume it's already there. |
| Hardcoded font paths (`/usr/share/fonts/truetype/...` at lines 53-54) fail on macOS | Out of scope for Phase 1 — that's Phase 3 BUILD-02. The maintainer is on Linux (per `.planning/codebase/STACK.md`), so verification on the maintainer's box succeeds. If a non-Linux contributor needs to run the script, the PR review will catch it; for now, accept the constraint. |
| Published markdown for one of the two unread releases (`glyphosate-weedkiller-halt.md`, `rural-deprivation-funding.md`) has a body shape that crashes the parser | Low — the parser is defensive (skips H1, skips strapline, skips ENDS markers, truncates on Media Contact, handles bullets/blockquotes/inline bold/italic/links). Task 4 will surface any crash. If a crash occurs, do not edit the parser — that's the wrong fix. Instead, inspect the offending markdown line and either edit the published markdown (if it's malformed) or accept the change and address it in Phase 2. |
| Regenerated PDFs differ visually from the committed ones because the published markdown was editorially polished after the original drafts | Expected per RESEARCH.md §5. Acceptable. The locked Q2 decision is that this PR does not commit regenerated PDFs, so the visual diff is observed-but-not-shipped. The committed PDFs that already went out remain the authoritative artefacts. |
| Future contributor runs the script and accidentally commits regenerated PDFs | Out of scope to prevent in Phase 1 — would need a `.gitattributes` or pre-commit guard, which is the kind of CI safety-net work scoped to Phase 4. For Phase 1, the PR description's explicit "do not commit regenerated PDFs" guidance is the mitigation. |
| Phase 2 EMBARGO-02 work needs the script to read from `_incoming/` again for embargoed drafts, undoing this change | This plan's `SOURCE_DIR` is a single line; Phase 2 can introduce a `--source-dir` argument or per-`Release` explicit paths without difficulty. RESEARCH.md §5 explicitly flags this and instructs not to over-engineer here. The minimum-change approach keeps Phase 2's design space open. |
| Optional `Release.src_md` → derived-from-slug refactor leaks into this plan as scope creep | Explicitly out of scope here — RESEARCH.md §5 marks it as "Optional refactor (recommended for legibility, ~5 line diff)" but the plan brief's Q2 framing and the "minimum-change fix" goal point at not bundling it. If a future Phase 2 plan benefits from the cleanup, it can do it then. |
